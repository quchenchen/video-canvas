# Seedance 音色库接入方案

> 目标：把方舟 cn-beijing 的 Seedance 参考音色接入资产库，可浏览、可试听、可在画布视频节点里作为参考音频。
> 数据日期：2026-11-19。数据从本机 `seedance` 库 `user_assets` 中核对得到，共 80 条真实 cn-beijing 音色；导入工具放在项目外，不进代码库。

## 1. 关键事实

| 事实 | 证据 | 影响 |
|---|---|---|
| 数据源是方舟 cn-beijing 的真实音色，不是源项目里残留的 BytePlus 国际站清单 | 本地 `seedance.user_assets` 80 条，音频与缩略图均带方舟官方 asset ID | 入库以这 80 条为准，不能拿 101 条国际站快照冒充 |
| Seedance 只认可方舟官方 `asset://<ID>` | 方舟控制台 cn-beijing 体验页；插件 1.3.0 给参考音频加 `filed: true` | Seedance 走 `asset://`，其他模型走转存后的音频文件 URL |
| 官方音色是系统公共素材，不属于任何用户 | `assets.user_id=0`、`source=official` | 所有人可读可引用，但写操作仍按原归属校验 |
| 现有素材模型没有缩略图 / 官方 ID 字段 | `backend/internal/model/asset.go` 原结构 | 必须加字段，纯导数据做不到 |
| 画布引用条与首页/后台参数面板不是同一套 UI | `TaskPromptPanel` 只渲染 `VideoParamPanel section="params"`，引用走 `RefStrip` | 入口必须挂在 `RefStrip`，只改 `RefCard` 画布里看不到 |

**结论：数据层要扩字段，生成链路要双轨，前端要在画布引用条里补入口；导入器只作为项目外工具临时使用。**

## 2. 架构

```text
输入：本机 seedance.user_assets（80 条 cn-beijing 官方音色）
  │
  ▼
导入工具【项目外一次性执行，不是产品代码】（校验 → 下载音频/缩略图 → 转存 → 写 assets 行）
  │
  ▼
数据层：assets 表（source=official, user_id=0 系统公共）+ 新增字段
  │
  ├──▶ 资产页「音色库」tab：缩略图 + 试听
  │
  └──▶ 画布视频节点引用条「+」→ 音色库 → params.audios
         │
         ├── Seedance 2.x：doubao-video 1.3.0 的 filed 标记 → 宿主换成 asset://<official_asset_id>
         └── 其他模型：保持转存后的音频文件 URL
```

### 数据模型（迁移 0044）

在 `assets` 表加三列，不建新表：

| 列 | 用途 |
|---|---|
| `thumbnail_key` | 缩略图在自有存储的 key；空表示没有 |
| `official_asset_id` | 方舟官方素材 ID；Seedance 生成时用它拼 `asset://` |
| `source=official` | 系统公共音色标记（`user_id=0`） |

不为音色单独建 `official_voices` 表：音色本质就是「一条 audio 素材 + 一张缩略图」，复用现有素材体系即可；新表只会制造并行模型。

## 4. 运行环境变更

- 本地 `video_canvas` 库已登记 `doubao-video@1.3.0`，并把 4 个方舟 Seedance 模型的发布配置升级到 1.3.0（新增 revision 2）。
- 官方音色数据：80 条 `kind=audio, source=official`，80 张对应缩略图；ID 集合一致，重复导入会跳过。
- 运行中的后端 Registry 缓存最多 30 秒自动刷新；无需为了这一步重启服务。

### 4.1 备案（filing / asset://）的适用边界

**虚拟人像库备案只适用于方舟 Seedance 与 BytePlus 渠道，其他视频模型不适配。** 判据是渠道 base_url，不是显示名：

| 渠道 key | 显示名 | base_url | 备案能力 |
|---|---|---|---|
| `a5e7a7f7…` | seedance-ark-cn | `ark.cn-beijing.volces.com` | 方舟国内站，已配 `filing_json`（zhongzuo 素材组） |
| `f4842494…` | seedance | `ark.ap-southeast.bytepluses.com` | BytePlus 国际站，具备备案能力（当前未启用） |
| `f4cf11d6…` | agnes-ai-intl | `apihub.agnes-ai.com` | 不适配，`filing_json={}` |
| 其余 | deepseek / claude / image | — | 不适配，`filing_json={}` |

- 备案配置是**渠道级**的：`ai_channels.filing_json`（`{enabled, group_id, project_name}`）+ `ai_secrets` 里的 AK/SK。它不属于模型，不能写进模型 `capabilities`。
- `filed: true` 只出现在 Seedance 用的 `doubao-video` 插件里；agnes 等非适配插件的音频引用是普通 `{__fileRef, as:"url"}`，宿主因此走 `Assets.Open` 拿真实音频文件 URL，不会拿到 `asset://`。这条分流由**插件是否声明 filed**决定，不是模型名。

### 4.2 故障复盘：模型 capabilities 里的错位 filing 导致 3 个 Seedance 模型下线

- **现象**：真实模型清单 `GET /models?kind=video` 只返回 1 个 Seedance（`m-d685fa4ef23d`），另外 3 个在画布里判定 offline、无法选中/无法用音色。
- **根因**：3 个模型的 `capabilities` 里有一个非法字段 `filing`（`{enabled, group_id, project_name, site}`，是渠道级备案配置的副本）。`modelcfg.ParseModel` 的字段白名单没有 `filing`（只有 context/ops/params/prompt/prompt_format/refs/system/video/vision），整模型被 `buildState` 忽略。日志 `ai_config_registry.go:154`「已启用的模型配置无法解析，已忽略」有明确记录。
- **非本次升级引入**：`filing` 在 revision 1（doubao-video 1.1.0 时代）就存在，1.3.0 升级只改了协议版本号。幸存模型 `m-d685fa4ef23d` 恰好没有该字段。
- **修复**：为 3 个模型各新增 revision 3，从 `capabilities` 删除 `filing` 并发布；revision 1/2 原样保留可追溯（原 filing 值见 rev2 或国内方舟渠道 `filing_json`）。修复后清单恢复 4/4，Registry 刷新后日志零报错。
- **判据**：排查「模型清单里少模型/画布 offline」先看 `ai_config_registry.go:154` 日志，别只看 `ai_models.enabled`；启用状态与能否进清单是两件事。

## 5. 不做的事

- 不把官方音色复制成每个用户的个人资产：会制造副本和归属问题，系统公共素材 + 引用即可。
- 不使用国际站 101 条快照冒充国内方舟资源。
- 不让普通用户通过 API 写 `source=official` 素材；写操作仍走用户归属校验。
- 导入器不进项目代码库，不作为后端 API 暴露。

## 6. 验收标准

1. `GET /assets/official?kind=audio` 返回 80 条，每条带可用缩略图与音频地址。
2. 资产页「音色库」能看到缩略图，点开能试听。
3. 画布视频节点引用条「+」→「音色库」能选音色；选中后 `params.audios` 含该 asset ID，当前方式不支持音频时自动切到「全能参考」。
4. Seedance 生成请求里参考音频是 `asset://<official_asset_id>`；其他模型仍是音频文件 URL。
5. 素材库弹框（角色卡「绑定已有」音色、画布音频节点填空）切到「音色库」能看到 80 条紧凑小卡，可勾选；选中后写进角色的 `voice.assetId`（片场/画布生成时随角色带入 `audios`）。
6. `bun test` 与后端检查通过；导入器在项目内零残留。

## 7. 片场与角色卡：音色的真正去向

音色在生成链路里只有一条入口：`input.audios`（素材 ID 数组）。片场（短剧 studio）没有单独的音频选择控件，它的参考音频完全来自**角色卡音色**——`character.voice.assetId` 经 `characterRefsOfNode` → `resolveBindings` 展开进 `audios`（见 `web/src/utils/tasks/capabilities.ts`、`web/src/utils/drama/segment-input.ts`）。所以「角色能绑定 音色库」等价于「片场能用 音色库」，不需要在片场另做入口。

角色卡音色是画布节点里的一个引用（`{mode:"audio", assetId, src, origin}`，见 `web/src/types/canvas.ts` 的 `CharacterVoice`），没有独立的后端角色表。官方音色作为 `source=official` 的公共素材，按 ID 可被任意用户读取，写进 `voice.assetId` 后生成时由后端 `FiledAssetResolver` 按插件分流（Seedance → `asset://`，其他 → 文件 URL）。

「绑定已有」音色现在走统一的 `AssetPickerDialog`，来源含「音色库」（紧凑网格，一行多列），与画布音频填空共用同一实现。

## 8. 两套公开资源与资源域判定（2026-11-19 修正）

原先把 `asset-xxx` 当成「导入账号的私有素材」，按渠道行绑定。实测与业务口径都不是这样：

- 方舟国内站（`ark.cn-beijing.volces.com`）与 BytePlus 国际站（`ark.ap-southeast.bytepluses.com`）**各自维护一套公开音色**，同一套里素材 ID 对所有账号通用，跨套直接 `The specified asset ... is not found`。
- 所以判定依据是**资源域**，不是渠道行、更不是账号：同一个域下换渠道（甚至删掉重建）仍然可用；跨域必须回退。

### 8.1 数据字段

| 列 | 含义 | 谁在用 |
|---|---|---|
| `official_asset_id` | 上游公开素材 ID（`asset-xxx`） | 拼 `asset://` |
| `official_scope` | 资源域：`ark-cn` / `byteplus`；空表示来源不明 | **唯一判定依据** |
| `official_channel_key` | 导入时的渠道 key，仅作溯源审计 | 不参与判定 |

`provider.ResolveChannelScope(declared, base_url)` 决议任务渠道的资源域，**渠道显式声明优先，域名推断降级为兜底**：

| 渠道 `voice_scope` | `base_url` 域名 | 决议结果 |
|---|---|---|
| 空 | 能认出（方舟 / BytePlus） | 按域名推断（老数据不填照旧跑） |
| 空 | 认不出来（自建代理） | 空串 → 只能用音频文件 |
| `ark-cn` / `byteplus` | 认不出来 | 用声明（代理后面也能走 asset） |
| `ark-cn` / `byteplus` | 能认出但与声明不同 | 空串 → 退化成文件 URL，并记一条 warn（配置冲突，宁可退化也不发错地址） |
| 未知取值 | — | 空串；管理端保存时直接拒掉 |

### 8.1.1 为什么改成渠道声明（2026-11-19 晚）

纯域名判断是打地鼠：每接一家自建代理 / 私有网关就得往 Go 里加一条域名规则，而且代理后面看不到真实域名。改成渠道字段后：

- 新渠道由运营在后台选「公开素材资源域」（留空 = 按 Base URL 推断），加代理不改代码；
- 迁移 `0047_channel_voice_scope.sql` 按 `base_url` 回填现有渠道，行为与改动前完全一致；
- 字段随渠道快照冻结进任务快照（`ChannelSnapshot.voice_scope`），执行侧不再实时看渠道行；
- 模型清单对外暴露 `voice_scope`（只有资源域，不含渠道地址），分镜据此做跨域提示。

这仍是**声明式**方案，不是插件化：公开音色的目录拉取、入库、缩略图、权限仍在宿主内核，只有「引用地址声明」挪到渠道配置上。

### 8.2 处置矩阵

| 最终视频模型 | 渠道资源域 | 音色资源域 | 实际传参 |
|---|---|---|---|
| Seedance（doubao-video，`filed:true`） | ark-cn | ark-cn | `asset://<official_asset_id>` |
| Seedance | byteplus | byteplus | `asset://<official_asset_id>` |
| Seedance | byteplus | ark-cn（跨域） | 音频文件 URL |
| Seedance | 任意 | 空（来源不明） | 音频文件 URL |
| 非 Seedance（agnes 等，无 `filed`） | — | — | 音频文件 URL，永不走 asset |

两条闸必须同时成立：**插件声明 `filed`**（只有 Seedance 插件有）**且资源域一致**。因此「方舟和 BytePlus 都没启用」时不存在可选的 Seedance 模型，音色只能作为普通参考音频文件被调用，不会出现任何 `asset` 地址。

### 8.3 实测证据（2026-11-19）

| 任务 | 模型 / 渠道 | 音色 | 结果 |
|---|---|---|---|
| 28 | 方舟国内 Seedance | 国内音色 | `succeeded`，请求里 `asset://asset-20260224190657-qm7zm` |
| 29 | BytePlus Seedance | 国内音色 | 修复前 `asset not found`；修复后回退文件 URL |
| 32 | 方舟国内 Seedance | 国内音色 | `succeeded`（回归，仍走 asset） |
| 33 | BytePlus Seedance | BytePlus 音色 | `succeeded`，走 BytePlus 自己的 asset ID |

本地开发环境没有公网 `storage.local.base_url`，回退成文件 URL 时上游拉不到（报 `invalid url`），这是环境限制不是逻辑错误；生产配了公网前缀即可。

### 8.4 数据现状

- `ark-cn` 80 条：来自本机 `seedance.user_assets`（国内公开音色）。
- `byteplus` 101 条：来自 `ark_seedance2.0_quickstart_package/docs/validation/byteplus-official-audio/materials-page-*.json`（ListExperienceVideoMaterials 抓包，208 条素材里的 101 条 audio），音频与 `audioIcon` 缩略图全部转存到自有存储。
- 两套合计 181 条，`/assets/official` 单页上限 100，前端按页取全量后按来源分组展示（方舟国内 / BytePlus 标签）。
- 导入器仍是项目外工具；导入时必须写 `official_scope`，否则该条永远只按文件 URL 使用（安全但失去 asset 形态）。

### 8.5 分镜上的跨域提示

`GET /models` 的每条模型带 `voice_scope`（只有资源域，不含渠道地址）。片场按提示词组装片段时（`utils/drama/segment-input.ts`）：

- 角色音色在绑定那一刻把 `scope` 记进 `CharacterVoice`（来自素材 DTO 的 `scope`），普通音频没有这个字段；
- `planSegmentInput({ voiceScope })` 比较「音色 scope」与「模型 voice_scope」，不同就给一条**非阻断**提示：

  > 林川 的音色与所选模型不同域，按音频文件参考（不使用 asset 引用）

- 模型没有 `voice_scope`（非 Seedance、代理渠道没声明）或音色不是公开音色时都不提示——那时本来就只有文件一条路，不必提醒；
- 提示只影响显示，不拦提交：真正决定发什么地址的是执行侧的 `FiledAssetResolver`。

已知边界：本次改动之前绑定的音色没有 `scope` 字段，不会触发提示（生成行为不受影响，后端仍按素材表里的 `official_scope` 判定）。重新选一次音色即可带上。

### 8.6 分类：语言（大类别）+ 人群（子类别）

界面上两级：**大类别是语言，子类别是人群**。两者都不是人工猜的：

| 类别 | 取值 | 数据来源 |
|---|---|---|
| 大类别 · 语言 | 中文 / English | **以来源为基准**：方舟国内那套是中文音色，BytePlus 那套是英文音色（`scope` → `zh` / `en`，见 `voiceLangOf`） |
| 子类别 · 人群 | 男孩 / 女孩 / 男生 / 女生 | 官方素材库标签「年龄-性别-名字」：方舟国内 80 条按 `official_asset_id` 一一对齐；BytePlus 101 条名字本身就是 `Age - Gender - Name`，直接拆 |

- 数据落在素材表：`voice_age`（child / teen / young / middle / older）、`voice_gender`（male / female）、`voice_lang`（zh / en），迁移 `0048_voice_profile.sql` 回填，181 条无一遗漏。
- 归类规则（`utils/assets/official-voices.ts`）：`child`、`teen` 两个年龄段算童声 → 男孩 / 女孩；`young`、`middle`、`older` 算成人 → 男生 / 女生。年龄仍完整存在数据里，以后想细分（例如单独筛「老年」）加一档即可。
- 语言用来源推导而不是直接读 `voice_lang`：分类基准与用户看到的两套素材一致，也不怕字段没回填；两者冲突时以来源为准。
- 方舟国内有 7 条导入时名字被截短（`小何2.0` → `小何`、`温柔女神` → `温柔女神2`），其中一条被写成占位名 `premium-default-avatar`（实为 `少年_少女-男-炀炀`，`asset-20260224190657-bj5zq`）。迁移按 asset ID 修正分类并顺手改回名字——**分类只能按 ID 对，不能按名字对**。
- 展示：卡片角标显示子类别（男孩 / 女孩 / 男生 / 女生），BytePlus 的显示名去掉「Age - Gender - 」前缀（`voiceDisplayName`），信息不重复。
